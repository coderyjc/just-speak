## 3. 技术选型与项目组织

### 3.1 固定技术路线

| 职责 | 采用方案 | 实现要求 |
| --- | --- | --- |
| 语言、界面 | Kotlin、Jetpack Compose、Material 3 | 手机布局、系统字体缩放、深浅主题 |
| UI 状态 | ViewModel、StateFlow、生命周期感知订阅 | UI 退出前台后，任务执行不依赖 UI 收集器 |
| 并发 | Kotlin Coroutines | 明确作用域、取消和资源释放；任务命令串行处理 |
| 麦克风 | Android `AudioRecord` | 分块读取，落盘与网络发送解耦 |
| 文件处理 | `MediaExtractor` + `MediaCodec` | 选择音轨、解码得到 PCM，只处理音频轨道 |
| 重采样 | Media3 `SonicAudioProcessor`，封装为内部接口 | 输出 16 kHz；speed、pitch 均为 1；正确 drain/flush |
| 网络 | OkHttp WebSocket + HTTP | 实现百炼 ASR 和 LLM 适配器 |
| 持久化 | Room、DataStore、应用私有文件 | Room 存任务；DataStore 存普通设置 |
| 凭据 | Android Keystore + AES-GCM | 加密保存用户 API Key |
| 文件访问 | Storage Access Framework，简称 SAF | `ACTION_OPEN_DOCUMENT` 导入，`ACTION_CREATE_DOCUMENT` 导出 |
| 长任务 | Android 前台服务 | 按当前实际工作设置服务类型 |
| 构建 | Gradle Kotlin DSL、版本目录、Gradle Wrapper | 依赖精确锁定，可在 Windows 构建 |

原生媒体解码、格式支持和音频处理能力依据 [S6]、[S7]、[S15]。首版不引入 Python、PySide6、Chaquopy、FFmpeg 或 NDK 构建链。对于超出核心验收范围的文件，检测能力后给出明确结果；扩展支持必须有样本验证。

### 3.2 工具链和工程位置

- 应用名：`JustSpeak`。默认 `applicationId` 与 `namespace`：`app.justspeak.android`；若仓库已有正式命名规则则沿用。
- `minSdk = 33`。根据已公布的 Android 17 SDK 配置，默认 `compileSdk = 37`、`targetSdk = 37`。[S1]
- 开工时核对 SDK 和工具链稳定发布状态。若执行环境中 API 37 仍仅为预览版，则采用官方最新稳定 SDK，并在开发记录中说明；不以绕过运行限制为目的降低 target。

- 单个 `app` 模块足以完成首版，通过包结构划分职责；无需提前拆成大量 Gradle 模块。

## 4. 页面与操作

保留主页、实时录音、文件转写、历史、设置五个入口，使用适合手机的导航。核心操作保持少量点击可达，技术参数收纳到设置中的高级区域。

| 页面 | 必须实现 |
| --- | --- |
| 主页 | 累计字数、录音/文件时长、活跃天数、最长记录、峰值日期、最近七天统计；未配置单价时费用显示“未设置” |
| 实时录音 | 场景、开始/暂停/继续/停止、音量指示、已录时长、网络状态、稳定原文与当前临时句；停止后切换三个文本阶段 |
| 文件转写 | 系统选择 MP4、展示文件名和时长、检测音轨、选择音轨、上下文提示、切片时长、开始/暂停/继续/取消、分阶段进度、单独导出 WAV |
| 历史 | 标题、来源、时间、状态、时长；原文/处理阶段切换、编辑最终文稿、复制、UTF-8 TXT 导出、分享、恢复、删除 |
| 设置 | 凭据、地域、Workspace、ASR/LLM 模型、语言、两个文本处理 Prompt、场景、切片长度、历史保留数量、估算单价、高级端点覆盖 |

行为约定：

- 开始按钮在请求处理中防重复触发，暂停和停止命令幂等。首版同一时间执行一个主动任务；暂停的任务不占执行槽，可从历史恢复。
- 录音暂停结束本次云端会话，保留当前逻辑任务；继续录音创建新的采集段和云端会话。暂停不触发 LLM。
- 停止录音后，先完成剩余 ASR 或缺口补转写，再按配置执行两个文本阶段；全部结果属于同一历史任务。
- 返回键、切页、旋转、Activity 重建均不表示停止任务。结束采集必须由任务命令完成。
- 原文和模型输出分阶段保存；用户编辑的最终稿独立保存，后续重试不覆盖人工编辑。
- 文件处理进度分别显示“准备音频、识别第 i/n 段、文本处理”。未完成全部片段时不得提前显示 100%。

## 5. 前台服务、权限和亮屏后台行为

### 5.1 生命周期责任

由一个 started foreground service（可命名 `TranscriptionService`）承载当前主动任务，内部持有独立协程作用域和任务执行器；Activity 可以绑定观察，但服务不能仅靠绑定存活。ViewModel 负责状态展示和发送命令。

录音入口顺序为：用户在可见页面点击开始 → 获取麦克风权限 → 启动服务并及时调用 `startForeground` → 初始化本地任务和采集 → 建立云端连接。任何失败都要释放已获取的资源，并保留可以恢复的文件。

Android 对麦克风前台服务的后台创建有限制，首次开始和暂停后的继续均默认从可见页面触发。通知提供“暂停”“停止”“返回应用”；暂停后继续时，引导返回录音页操作。[S2]

### 5.2 权限与类型

Manifest 按实际使用声明 `INTERNET`、`ACCESS_NETWORK_STATE`、`RECORD_AUDIO`、`POST_NOTIFICATIONS`、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_MICROPHONE`、`FOREGROUND_SERVICE_DATA_SYNC`、`FOREGROUND_SERVICE_MEDIA_PROCESSING`。新 API 类型在运行时按系统版本选择，禁止在旧系统传入不支持的类型位。

| 当前执行阶段 | 运行时前台服务类型 |
| --- | --- |
| 麦克风持续采集并实时转写 | `microphone` |
| MP4 解码、重采样、生成标准音频 | API 35+：`mediaProcessing`；API 33–34：按本地文件处理使用 `dataSync` |
| 文件 ASR、已保存音频补转写、LLM 请求 | `dataSync` |
| 暂停后无实际工作，或任务结束 | 停止前台状态并释放服务资源 |

服务在 Manifest 中声明可能使用的类型，运行时只启用当前工作需要的类型。麦克风释放后进入网络处理阶段，应更新运行类型；不持续挂着麦克风类型维持无关任务。[S2]

通知权限单独申请。用户拒绝后，不能把它误判为麦克风权限失败；Android 13+ 仍允许前台服务运行，其提示展示位置有所不同。页面解释无法使用通知栏控制，并保留应用内停止入口。[S3]

文件导入通过用户选择器授权，不申请“管理所有文件”、整库媒体读取、无障碍或悬浮窗权限。

### 5.3 后台运行边界

- 必须通过：亮屏、按 Home 或切换其他 App，录音与网络发送继续；返回后状态和文本衔接正确。
- 不要求全局保持屏幕常亮。可以只在 JustSpeak 的活动任务页面设置 `FLAG_KEEP_SCREEN_ON`；切换其他 App 后，屏幕状态由系统和当前 App 决定。
- 不添加长期 WakeLock、开机自启、守护进程或自动拉起录音。首版不要求用户先修改一整套省电设置。
- 若某个实测机型的系统限制导致中断，记录可复现条件，提供针对该机型的说明；不把正常静音视为系统阻断。
- 通过录音配置回调等系统信息检测采集被静音/占用。来电或其他 App 占用麦克风时，标记中断并暂停采集，用户回到页面后恢复。系统音频共享策略参见 [S5]。
- 使用 `START_NOT_STICKY`，进程死亡后不自动重启麦克风。下次进入应用，从数据库恢复已保存音频的处理。未采集到的声音无法补回。
- 处理 API 35+ `dataSync`/`mediaProcessing` 的 `onTimeout`：快速保存状态、停止工作并退出服务，后续由用户恢复。这两类服务存在后台累计运行限额；系统亮屏不能替代该限制。[S4]

首版不依赖 WorkManager 承载整场实时采集或整小时的持续转写。以后若增加可延迟调度，再评估引入；Android 16 的长 Worker 配额变化见 [S14]。

## 6. 实时音频与断网处理

### 6.1 采集和格式

统一送入 ASR 的数据为 **16 kHz、单声道、16-bit signed PCM little-endian**。WebSocket 的二进制音频帧不携带 WAV 头。

- AudioRecord 优先尝试所需格式，检查初始化状态、最小缓冲区及实际输出参数；失败时尝试设备支持的 48 kHz/44.1 kHz，再转换到目标格式。
- 首版跟随系统可用的麦克风输入，主验收使用手机内置麦克风；无需录音设备选择器。不会通过播放视频来间接完成文件转写。
- 采集线程只做必要的读取、转换和本地写入；网络在另一条受控处理路径工作，不能阻塞采集。
- 采集段持续写入私有目录中的 PCM；段结束后补齐/生成 WAV 信息。每个处理块保持完整采样帧，不在每个小块重新创建重采样器。
- 重采样器统一封装 `configure / queue / drain / finish / reset`，正常结束时排空尾部缓存，格式变更时重新配置。Media3 方法签名以锁定版本为准，尤其注意输出缓冲区的消费时机。[S7]
- PCM16 双声道转单声道使用避免整数溢出的混合与限幅。解码器输出浮点 PCM 时先按实际格式归一化转换，不能直接将其字节当成 PCM16。

### 6.2 本地音频为可恢复依据

先保存音频，再通过文件偏移或有界队列交给网络发送器。建议每 1 秒更新一次本地采集进度，每 5 秒及暂停/停止时刷新持久化检查点。区分“已读取帧、已写入帧、已确认持久化帧”，恢复时以有效文件长度和检查点的安全交集为准。

网络队列默认最多暂存约 5 秒音频。持续积压超过阈值时结束失效云端会话并标记待补区间，本地录音继续；不无限增长内存，也不静默丢弃录音。

时长使用样本计数及单调时钟计算。一个逻辑录音任务可包含多个采集段，保存各段的墙钟开始时间、样本偏移和中断原因；暂停时长不计入实际录音时长。

### 6.3 断网、重连和补转写

1. 网络故障时保留已确认文本；临时句单独标识，不能冒充完整结果。
2. 麦克风仍可用且磁盘正常时继续录音，页面/通知显示“录音中，部分内容待补转写”。
3. 网络恢复后创建新的云端任务，优先接入当前音频，保持当前讲话的响应速度。
4. 从上次可靠结果附近至新会话接入点的音频登记为待补区间；保守保留短重叠，并沿用第 8 节合并规则。服务端最终句的时间戳不能被当成每个 PCM 字节的接收确认。
5. 用户停止后，依次补转写这些区间，再形成完整原文和可选 LLM 输出。仍无网络时，保存为可恢复状态。

连接瞬时失败最多连续尝试 3 次，含首试，间隔默认 2 秒、5 秒并加少量抖动。之后保持本地录音和明确状态，由用户重试或网络重新可用事件发起下一轮。鉴权/模型参数错误不做循环重试。

如果云模型存在明确的单会话时限，则在低于该限制时轮换连接，采集保持独立；不能为了延长云端会话而停止用户的逻辑录音。对应能力在 Provider 中集中管理，并纳入 60 分钟验收。

## 7. 百炼接口适配

### 7.1 适配层及配置快照

首版实现 `DashScopeAsrProvider` 和 `DashScopeLlmProvider`。上层依赖内部事件接口，协议 JSON 留在 Provider 内；测试提供 Fake Provider 和模拟 WebSocket 服务。

新任务保存：地域、Workspace、ASR 模型、LLM 模型、语言、有效端点、ASR 提示、两个 LLM Prompt、切片参数、处理算法版本、凭据引用。API Key 明文不进入快照。设置修改仅影响后续新任务；恢复任务使用原快照。

ASR 默认模型沿用桌面版：`qwen-audio-3.0-asr-flash-streaming`。用户可编辑；模型不可用时展示服务端原因，不能静默换模型。LLM 模型默认留空，代表跳过后处理。

### 7.2 端点与鉴权

| 地域 | Workspace 专属域名 |
| --- | --- |
| 北京 | `{WorkspaceId}.cn-beijing.maas.aliyuncs.com` |
| 新加坡 | `{WorkspaceId}.ap-southeast-1.maas.aliyuncs.com` |

填写 Workspace 时按对应域名生成 ASR URL `wss://域名/api-ws/v1/inference`，LLM Base URL `https://域名/compatible-mode/v1`；后者通过 `POST /chat/completions` 调用。未填写 Workspace 时使用官方仍保留的地域公共端点：北京 `dashscope.aliyuncs.com`，新加坡 `dashscope-intl.aliyuncs.com`。用户账号下的实际可用性及业务空间要求在联调时核对。[S8]、[S11]

高级设置分别提供 **ASR WebSocket URL** 和 **LLM Base URL** 覆盖，避免两种协议地址混用。鉴权使用请求头 `Authorization: Bearer …`；按官方要求处理 Workspace。限制正式请求使用 TLS，避免跨域重定向时携带凭据。

### 7.3 ASR 协议约定

调用顺序固定为：连接成功、发送 `run-task`、等待 `task-started`、持续发送 PCM 并接收结果、发送 `finish-task`、继续接收最终结果、收到 `task-finished` 后关闭连接。[S8]

每次云端尝试生成新的 UUID `task_id`。基本配置为 `task_group=audio`、`task=asr`、`function=recognition`、`streaming=duplex`、`format=pcm`、`sample_rate=16000`。语言和上下文按模型支持的字段发送，不把 LLM 的 Prompt 字段直接复制进 ASR 请求。[S9]

默认以约 100 ms 音频为网络发送单元，对标准 PCM 即 3200 字节；这是网络帧，与分钟级文件切片分开处理。文件模式首版按约 1× 音频速率发送；只有官方约束与真实联调都支持时再提高。不要把整小时音频一次塞进 OkHttp 队列。

这一默认方案直接使用已有流式模型，无需公网文件 URL 或新增对象存储。其预期耗时可能接近素材时长并增加切片重叠、网络和 LLM 时间；“支持一小时文件”不代表“一小时文件几分钟完成”。

结果处理要求：

- `result-generated` 中 `sentence_end=false` 更新当前临时句；为 `true` 时提交最终句。幂等键包含云端尝试 ID 和 `sentence_id`，不同连接的句号序号不能混用。[S10]
- `heartbeat=true` 的事件不追加正文。显示层将稳定句和临时句分开，避免每次更新都把整段文字追加一次。
- 回调携带所属尝试及连接代次；已过期连接的迟到事件只能归入原尝试，不能覆盖当前临时句、推进新任务状态或再次提交正文。
- 保存句/字时间戳及该云端会话的音频起点，将相对时间转换为任务内位置，支持重连和切片合并。
- `task-finished` 前继续接收尾部最终句；发送 `finish-task` 后立刻关闭连接会丢失收尾结果。
- `task-failed`、握手失败、关闭、超时统一映射为可恢复/不可恢复错误，保留服务端错误码及请求/任务 ID。
- 每个尝试的 `usage.duration` 单独维护最新值或累计最大值，不把每个最终句中的任务累计时长重复相加。[S10]

ASR 上下文入口沿用桌面“术语、人名、产品名”用途。实现时读取桌面适配代码及当前模型文档，将提示映射到支持的上下文/热词机制；限制长度并告知超限，禁止静默提交不支持的参数。配置、模型能力判断和请求构造需有协议测试。[S9]

## 8. MP4 文件转写

### 8.1 导入和音轨检测

使用系统文件选择器取得 `content://` URI，通过 ContentResolver 访问，不能强行转换为普通绝对路径。对 `ACTION_OPEN_DOCUMENT` 取得的授权调用持久 URI 授权；共享入口等临时授权或不可随机读取的来源，则复制到任务私有目录后处理。[S12]

扫描所有音轨，显示序号、MIME、语言（如有）、声道和采样率。只有一条可用音轨时默认选中；多条音轨时由用户选择。无音轨、加密轨、不支持编码、损坏文件需要在准备阶段说明。

主验收使用常见 MP4 + AAC-LC，44.1 kHz/48 kHz、单/双声道；额外支持的配置依实际解码能力和样本测试确定。不能只根据 `.mp4` 扩展名认定可解码。

### 8.2 标准化音频

选中音轨后，MediaExtractor 读取压缩音频，MediaCodec 解码，再混音与重采样为标准 PCM，流式写入任务目录。无需解码视频画面。

记录解码输出实际格式并处理格式变更，循环完整排空 EOS。检查输出时长、样本数以及 AAC 首尾延迟处理，避免重复裁剪。完成后原子写入有效性标记，允许从标准音频直接导出 WAV。

首版在解码完成后开始切片识别。如果准备阶段中断，可以从原文件重新完成标准化；如果 ASR 阶段中断，必须复用已经验证完整的标准音频。两者在界面上明确区分，不能承诺准备阶段也能精确断点续解码。

### 8.3 分片定义

默认片长 180 秒，可选 60–600 秒；相邻片段重叠 10 秒。以整数样本索引定义范围 `[startFrame, endFrame)`。以下公式统一使用样本数：`T = totalFrames`、`L = chunkSeconds × 16000`、`O = 10 × 16000`。

- 首片从 0 开始，终点为 `min(L, T)`。
- 若本片终点已到 `T`，结束；否则下一片起点为本片起点加 `L-O`。
- 所有片段非空，完整覆盖音频；不足一个片长的文件仅生成一个片段，末尾不额外生成仅含重复内容的片段。

完整 PCM 是统一音频源。优先按范围读取，至多保存当前需要的少量临时切片，避免为全部片段复制完整数据。

片段顺序提交，同一时刻一个云端尝试。用户点击暂停后，当前正在识别的片段完成再暂停；显示“本段结束后暂停”。取消则及时停止发送、关闭连接，将该片段记为未完成，并保留已经完成的片段。

若用户在准备音频阶段暂停，则停止解码并保留来源授权；继续时重新准备标准音频。不要显示“本段结束后暂停”后长时间没有反馈。准备阶段和识别阶段的暂停行为分别测试。

### 8.4 恢复与结果合并

每个片段独立记录范围、状态、尝试和结果。恢复只处理未完成片段，不能重跑所有已完成片段；中途失败的片段可从片头重做，原有部分结果标记为旧尝试，不能再拼接一次。

相邻结果合并优先使用时间戳和重叠区间中的文本对齐。仅在共享音频范围中判断重复；跨切点的句子需要细化到字词或保守文本对齐。保留两个原始片段结果，合并输出可重新计算。

若词时间戳缺失，采用受时间窗口约束的后缀/前缀匹配。匹配不可靠时保留内容并标记待检查；不得按固定字数裁切，也不得在全文中删除所有相似句。实际讲话中的重复表达必须保留。相同规则用于实时重连后的补转写。

保存完成片段结果、更新片段状态和提交进度需具备事务/原子性：先将结果文件原子落盘，再在数据库事务中提交其引用及完成状态。应用重启时清理孤立临时文件，不能把仅有“完成”标记但无结果的片段当成成功。

## 9. LLM 文本流水线

LLM 模型为空时，只保存识别原文；配置后默认在完整原文准备好时依次执行文本清晰、定向修复。两个阶段都保留输入版本、Prompt 快照、模型、输出、状态、尝试记录和响应中的 usage。[S11]

| 阶段 | 处理要求 |
| --- | --- |
| 识别原文 | 保留 ASR 内容，仅做必要的片段合并和结构整理 |
| 文本清晰 | 补标点、分段，改善明显口语断裂；保留事实、语义、数字、单位和专业术语，不改写成摘要 |
| 定向修复 | 根据用户的术语、人名、产品名及自定义要求修复；对无法判定的专名保留原文，不随意补全事实 |
| 最终文稿 | 默认取最后一个成功阶段；人工编辑独立存储 |

若能获取桌面版默认 Prompt，优先复用；否则按以上原则编写中文默认 Prompt，允许用户编辑。明确把待处理转写稿作为数据，稿件中出现的指令性文字不改变处理任务。

长文本默认按段落切成不超过约 4000 个 Unicode 码点的处理块，可以携带至多约 500 个码点的前文作为只读上下文。分别标识上下文与本块，要求仅输出本块处理结果，避免重复拼入前文。

字符预算只是保守工程起点，不能当成所有模型通用的 Token 上限。将预算与模型配置关联；发生上下文超限时缩小块长后重试，输出被截断时视为未完成，不能悄悄裁掉后半篇。保存块级检查点，重启后只重做未完成块。

阶段失败保留之前的成功文本和错误说明，可从该阶段重试。文本清晰失败时，定向修复保持等待，用户仍可查看及导出原文。用户取消后处理不影响录音或原始识别结果。若存在未补转写音频，默认先等待补全；用户主动选择基于现有原文处理时，标识其输入不完整。

## 10. 数据模型、恢复与统计

### 10.1 建议数据实体

字段名称可调整，语义和幂等约束必须保留。所有音频样本位置、毫秒时间及字节偏移使用 64 位整数。

| 实体 | 必需信息 |
| --- | --- |
| `Task` | ID、录音/文件类型、标题、创建/更新时间、总体状态、当前阶段、配置快照、凭据引用、有效音频样本数、原文版本、用户编辑稿 |
| `SourceMedia` | 原 URI、持久授权状态、可选私有副本路径、文件名、大小、音轨信息、来源指纹、标准音频路径及完整性状态 |
| `CaptureSegment` | 采集段 ID、任务内音频起点、墙钟开始时间、PCM 路径、已写入/持久化帧数、结束原因 |
| `RecognitionUnit` | 文件片段或补转写区间、起止样本、顺序、状态、当前成功尝试 ID、结果文件、合并算法版本 |
| `AsrAttempt` | 独立尝试 ID、云端 task/request ID、单元/采集段引用、音频起点、状态、已发送范围、最终句、最新 usage、错误、重试序号 |
| `TextStage` / `TextBlock` | 原文版本、阶段、块序号、输入范围、Prompt、输出位置、状态、usage、错误 |
| `Scenario` | 名称、地域、模型、语言、提示等普通配置；不包含明文 Key |
| `UsageLedger` | 唯一事件键、任务/尝试引用、统计日期、业务时长/字数、费用依据、模型单价快照 |

任务状态可采用 `DRAFT`、`PREPARING`、`RECORDING`、`TRANSCRIBING`、`POSTPROCESSING`、`PAUSED`、`WAITING_NETWORK`、`WAITING_CREDENTIAL`、`RECOVERABLE`、`COMPLETED`、`CANCELLED`、`FAILED`。

录音进行时，将采集状态与网络状态分开：断网后的任务仍处于录音状态，同时 ASR 显示离线/待补，不能用一个“失败”状态掩盖麦克风仍在工作。状态变化在任务执行器内串行处理并持久化。

### 10.2 文件组织和恢复原则

任务音频与结果位于应用持久私有目录 `filesDir/tasks/<taskId>/`，内容包含采集 PCM、标准 WAV/PCM、识别结果、文本阶段输出及必要的元信息。只有可重建内容进入 `cacheDir`；待转写音频不能仅放在可能被系统清除的缓存目录。

Room 为任务状态权威来源，文件内容与数据库通过版本和路径关联。若沿用桌面 `manifest.json`，将其作为可重新生成的诊断快照，避免出现两个互相覆盖的状态来源。

重启应用时执行一次恢复扫描：

1. 检查数据库中上次仍为执行中的任务，结合当前服务存活状态，将无执行器的任务标为可恢复。
2. 验证音频文件长度、帧对齐与完整性；PCM 可按有效帧数重建 WAV 头。尚未完整的解码输出不直接当成标准音频使用。
3. 保留已确认的最终句及已完成片段；旧的临时句和失败尝试结果单独保留诊断信息，不再次提交正文。
4. 需要原媒体但 URI 已失效时，让用户重新选择原文件，并核对文件指纹/音轨；来源不一致则新建任务，不能把两个文件的结果混合。
5. 凭据缺失时进入待填写状态；等待用户选择恢复，不能自动开始录音或无限制重跑云端请求。

暂停是可继续状态，取消也保留已完成内容和源音频；删除才执行清理。恢复过程中再次收到暂停/取消命令，应保持状态一致。

### 10.3 历史清理

默认保留最近 50 个可清理历史任务，可调整 10–600。正在执行、暂停、等待补转写或可恢复的任务不参与自动清理。自动清理数量不足时，提示存在未完成任务占用空间，不越过保护条件。

删除只操作数据库记录及应用创建的对应任务目录，先停止并确认任务不再写入，再删除。外部输入 URI 指向的原文件和用户自行导出的文件保持独立；路径删除需校验归属，不能根据任意配置路径递归删除。

### 10.4 统计口径

- **业务音频时长**：录音按实际采集样本计；文件按选定音轨的有效长度计。重叠与失败重试不重复增加业务时长。
- **业务字数**：首次形成完整原文时记录一次。首版默认按去除空白后的 Unicode 码点计数；LLM 输出、人工编辑和重复回调不再次增加累计字数。未完成任务可以另显临时字数。
- **云端用量**：按独立 ASR 尝试或 LLM 请求记录。请求重试可能增加用量；本地任务恢复幂等不等于云端计费幂等。
- **费用**：按用户配置的单价及可获得的用量估算，标注“估算”；无单价时不显示伪造金额。桌面文档中的 `0.00033 元/秒` 不视为所有模型的当前价格。
- **Token**：只展示接口实际返回的值。缺失时显示未提供，不根据字符数冒充服务端 Token。
- **累计台账**：事件有唯一键，重复完成回调不重复记账；清理历史不会级联删除已累计统计。
- **日期与峰值**：记录实际业务发生日期和时区；补转写不会把原录音时长再次记到补转写当天。

## 11. 凭据、存储与日志

API Key 支持“仅本次使用”和“保存到设备”。前者只保留在进程内，进程结束后需要重新输入；后者使用 Keystore 中的 AES 密钥加密 API Key，将密文、独立随机 IV 和必要版本元数据保存在应用私有存储。[S13]

- Keystore 管理的是加密密钥，API Key 作为待加密的数据处理。每次加密使用新的随机 IV，不能固定 IV。
- 任务快照只存凭据 ID，不存明文或可用于直接调用 API 的备份字段。
- 同一凭据配置的替换需有版本/新引用，旧任务仍定位原引用；原凭据被删除后，旧任务进入待配置状态。
- 后台转写过程中需要使用凭据，首版不启用每次解密都要求生物识别的策略。
- 数据库、音频和凭据默认不进入系统云备份/设备迁移；配置备份规则，并验证卸载、重装和密钥失效后的提示。不要让恢复出的密文被误认成有效 Key。
- 正式版本不记录请求头、API Key、音频 Base64 或完整文稿到常规日志。必要的原始识别响应存入任务私有文件，按任务清理。
- 日志只保留有限大小，例如总量不超过 5 MB，包含任务 ID、阶段、错误码、网络状态及耗时。诊断导出不自动附带音频和全文。

音频只发送至用户配置的 ASR 端点；启用 LLM 后，相关文稿发送至其配置端点。配置页用简短文字说明这一数据流。首版不集成统计 SDK、自建中转或固定的开发者 API Key。

空间策略：标准 PCM 每小时约为 `16000 × 2 × 3600 = 115200000` 字节，约 115 MB/110 MiB。空间估算同时考虑原媒体副本、标准音频与临时输出。

准备任务前检查预计空间，写入中持续检查和处理 I/O 失败。低于预设余量（默认 100 MiB，可在实现验证后调整）时安全暂停/结束采集，保存已完成内容并说明原因。文件来源大小未知时同样需要运行时检查。

## 12. 默认参数和错误处理

这些数值是首版工程默认值，集中维护；联调调整后记录实际值。

| 参数 | 默认值或规则 |
| --- | --- |
| 标准音频 | 16000 Hz / mono / PCM16 LE |
| 文件片长、重叠 | 180 秒，可调 60–600 秒；固定重叠 10 秒 |
| 网络音频块 | 约 100 ms；标准 PCM 为 3200 字节 |
| 文件发送速率 | 默认约 1× 实时速率 |
| 待发送内存缓冲 | 上限约 5 秒音频 |
| UI 更新 | 临时文本/音量节流到约 5 次/秒，最终句及时提交 |
| 通知更新 | 不高于约 1 次/秒，状态改变可立即更新 |
| 连接/启动/收尾等待 | 15 秒 / 20 秒 / 30 秒，超时保留可恢复数据 |
| LLM 单块请求 | 默认总超时 180 秒；不等同于整项任务超时 |
| 瞬时请求失败 | 最多 3 次尝试，含首试；默认重试间隔 2、5 秒 |
| 历史条数 | 50，可调 10–600；未完成任务受保护 |
| 费用单价 | 未配置，用户填写后显示估算 |

WebSocket 不设置覆盖整场录音的短总超时。未收到识别句也可能是安静环境，不能仅凭“长时间没文字”判定网络断开；结合连接状态、发送进度、协议心跳和当前 Provider 能力判断。

错误至少分为：权限缺失、麦克风不可用/被占用、无网络、服务暂不可用、限流、凭据错误、地域/模型/参数不匹配、不支持的媒体、文件授权失效、磁盘不足、服务超时、应用中断。

每类错误明确当前音频是否仍在保存、已完成内容是否保留以及下一步动作。401/403、非法参数、文件格式不支持等错误不盲目自动重试；429 遵循服务端重试指示。文件自动重试仍需保留各次尝试和可能增加的用量。

## 13. 实施顺序与阶段产物

| 阶段 | 工作 | 阶段完成标准 |
| --- | --- | --- |
| A：可构建基础 | 工程、主题、导航、配置、Room、凭据、日志；整理版本锁定 | 可安装空壳应用，配置持久化，数据库基础测试通过 |
| B：录音完整闭环 | AudioRecord、持久采集、前台服务、通知、真实 ASR、暂停/继续/停止 | 亮屏切 App 后持续转写，停止后可查看与导出原文 |
| C：MP4 完整闭环 | 文件授权、音轨检测、解码/重采样、切片、顺序 ASR、合并与恢复 | 常见 MP4 可转写，暂停及重启后从未完成片段继续 |
| D：文稿与管理 | 双阶段 LLM、长文本分块、场景、编辑、历史清理、统计、WAV/TXT 导出 | 桌面版核心业务流程在手机上完整可用 |
| E：稳定性与交付 | 长任务、断网、进程终止、权限与磁盘异常验证；修复并更新说明 | 第 14 节验收有对应记录，交付源码与 APK |

优先完成真实链路；涉及云端暂不可用时，用协议模拟继续开发其他模块并保留联调入口。功能按钮不能长期停留在占位状态。平台适配差异写入开发记录，不通过大量空接口推迟实现。

## 14. 测试与验收

### 14.1 自动化测试

重点测试会造成音频丢失、结果重复、状态损坏或重复计数的逻辑，无需为每个界面控件编写机械测试。

| 测试主题 | 必须覆盖的断言 |
| --- | --- |
| 重采样与 PCM | 44.1/48 kHz 到 16 kHz，样本数与时长、尾部排空、mono/stereo、PCM float/16-bit；使用已知频率信号检查速度/音高没有改变 |
| 切片范围 | 短于片长、恰好一个片长、跨边界、60 分钟、最终短片；无空片、不丢音频、重叠恰为设定值 |
| 重叠合并 | 跨切点句、不同标点、中英混合、故意重复讲话、缺失时间戳；不丢非重叠内容，失败时可重建 |
| ASR 协议 | 等待 task-started、临时/最终句、重复回调、跨连接 sentence_id 重用、心跳、收尾迟到、task-failed、旧连接迟到事件 |
| 暂停/停止并发 | 重复点击、网络回调与取消竞态、停止后资源释放；只有一个有效执行器提交当前任务 |
| 任务恢复 | 写结果前后分别中断、准备阶段中断、部分识别、原 URI 失效、缺失凭据、损坏尾部音频 |
| 统计 | 重试及重复事件不增加业务时长/字数；按尝试更新用量；历史删除不清空累计台账 |
| LLM | 超长输入分块、上下文超限、输出截断、阶段失败、重试恢复、人工编辑保护 |
| 文件与凭据 | 仅会话 Key 失效、加解密、普通设置和快照无明文 Key、任务路径归属、未完成历史保护 |

模拟 WebSocket 应能注入断开、延迟和重复事件。关键音频测试包含实际解码样本，不能仅测试与实现相同的切片公式。

| T08 | 文件识别中暂停、关闭进程、重开 | 已完成片段不重跑，标准音频复用，未完成片段可恢复 |
| T09 | 准备阶段进程终止 | 识别出不完整音频，能够从源媒体重新准备，原文件保持完好 |
| T10 | 无音轨/异常 MP4 | 明确提示原因，无永久转圈、崩溃或错误“成功”状态 |
| T11 | 通知权限拒绝、麦克风权限拒绝 | 分别处理；通知拒绝不被当成麦克风失败，麦克风拒绝时不启动录音 |
| T12 | 来电或其他应用抢占麦克风 | 根据系统状态显示中断，已保存音频保留；用户可从页面继续 |
| T13 | 文本处理成功/失败/超长文稿 | 三阶段独立，失败保留上游结果，长稿无静默截断，编辑稿不被覆盖 |
| T14 | 空间不足、历史清理 | 安全结束写入，已完成结果保留，输入原文件及未完成任务不被误删 |
| T15 | TXT/WAV 导出和分享 | UTF-8 中文正常，WAV 时长/格式正确，其他应用可打开 |
| T16 | API 35+ 服务超时及较新系统 | 超时正确退出并可恢复；记录 API 36/37 上的运行结果及适配差异 |

至少覆盖 API 33 和一个 API 34+ 环境；API 35/36/37 根据可获得的模拟器与手机补充差异验证。麦克风质量及 60 分钟后台采集必须在真实手机验证，模拟器不能替代这两项。

由于用户尚未指定品牌，首版不宣称已经适配所有厂商系统。实测报告记录型号、系统版本、应用版本、网络条件、测试时长、结果和发现的问题。

60 分钟测试分开记录：本地采集/解码管线、协议模拟、真实云端调用。缩短测试或模拟结果不能冒充完整实测。云端识别准确率、响应时间与手机采集连续性分别评价。

## 15. 构建与最终交付

在 Android 工程根目录提供下列标准命令；所选插件若产生不同任务名，应在 README 写出实际可执行命令。

```powershell
.\gradlew.bat testDebugUnitTest
.\gradlew.bat lintDebug
.\gradlew.bat assembleDebug
.\gradlew.bat connectedDebugAndroidTest
```

前三条用于本地构建检查，最后一条需要连接设备或启动模拟器。优先通过 USB 真机调试，开发电脑无需部署 ASR 模型或安装 CUDA。开发者机器路径进入 `local.properties` 等本地配置，不能写死进构建脚本。

必须交付：

1. 完整 Android 工程，包括 Gradle Wrapper、固定依赖版本和应用源码。
2. 可安装的开发测试 APK，并说明路径、版本、是否启用测试能力；正式连接能力必须真实可用。
3. `README_ANDROID.md`：Windows 环境配置、构建、安装、Key 配置、常见故障、支持格式和后台使用说明。
4. `IMPLEMENTATION_NOTES.md`：实际技术版本、与本文的实质差异、接口核验结果及原因。
5. `TEST_REPORT.md`：按 T01–T16 标注已通过/失败/未执行，附必要证据；列出剩余限制。
6. `THIRD_PARTY_NOTICES_ANDROID.md`：实际引入组件与许可来源，延续项目的开源说明；不将桌面专用组件名单机械复制过来。

配置可选 release 签名入口，证书和密码保存在本地环境，不提交仓库。未配置正式签名时如实交付测试 APK，注明后续升级安装需要保持签名一致。无需创建远程发布、上架或中转服务才能完成本任务。
